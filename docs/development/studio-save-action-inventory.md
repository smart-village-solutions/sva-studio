# Inventur der Save-Actions

Diese Inventur ist die verbindliche Abgrenzung für den Change `standardize-save-action-feedback`. Sie erfasst alle Form-Submits in der Studio-Oberfläche. Als normale Save-Action gilt nur eine Mutation, die einen im aktuellen Formular bearbeiteten Datensatz dauerhaft anlegt oder aktualisiert.

## Normale Save-Actions

| Bereich                    | Flows                                                                                             | Erwartetes Feedback                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Account                    | Profil; Inhaltsregeln                                                                             | Gemeinsamer Save-Button, feldnahe Validierung, persistenter technischer Fehler                                              |
| IAM                        | Löschregeln                                                                                       | Gemeinsamer Save-Button; der Autorisierungs-Testlauf bleibt eine Operation                                                  |
| Benutzerverwaltung         | Benutzer anlegen und bearbeiten                                                                   | Create wechselt auf die Detailseite; Update zeigt den gespeicherten Zustand im Button                                       |
| Gruppen                    | Gruppe anlegen und Stammdaten bearbeiten                                                          | Create wechselt auf die Detailseite; Update zeigt den gespeicherten Zustand im Button                                       |
| Rollen                     | Rolle anlegen; Stammdaten und Berechtigungen bearbeiten                                           | Create wechselt auf die Detailseite; Update zeigt den gespeicherten Zustand im Button                                       |
| Organisationen             | Organisation anlegen und Stammdaten bearbeiten                                                    | Create wechselt auf die Detailseite; Update zeigt den gespeicherten Zustand im Button                                       |
| Rechtstexte                | Rechtstext anlegen und bearbeiten                                                                 | Create wechselt auf die Detailseite; Update zeigt den gespeicherten Zustand im Button                                       |
| Instanzen                  | Normale Konfiguration einer bestehenden Instanz bearbeiten                                        | Gemeinsamer Save-Button; Provisionierung und Setup bleiben getrennte Operationen                                            |
| Schnittstellen             | Schnittstellen-Einstellungen anlegen und bearbeiten                                               | Gemeinsamer Save-Button; technische Fehler bleiben im Dialog persistent                                                     |
| Generischer Content-Editor | Datensatz anlegen und bearbeiten                                                                  | Create wechselt auf die Detailseite; Update zeigt den gespeicherten Zustand im Button                                       |
| Content-Plugins            | Cockpit Cards, Events, FAQ, Generic Items, News, POI, Projects und Surveys anlegen und bearbeiten | Gemeinsame Save-Primitives; Create wechselt auf die vorhandene Detailseite                                                  |
| Waste-Einstellungen        | Plugin-Einstellungen, PDF-Ausgabe und E-Mail-Erinnerungen                                         | Gemeinsamer Save-Button und persistenter technischer Fehler                                                                 |
| Waste-Stammdaten           | Orte, Straßen, Hausnummern, Regionen, Fraktionen und Sammelstellen anlegen und bearbeiten         | Gemeinsamer Pending-Zustand; geschlossene Dialoge zeigen den neuen oder geänderten Datensatz unmittelbar in der Elternliste |
| Waste-Planung              | Touren, Zuordnungen und globale beziehungsweise lokale Planungen anlegen und bearbeiten           | Gemeinsamer Pending-Zustand; geschlossene Dialoge zeigen das Ergebnis unmittelbar im Planungsbereich                        |

## Begründete Ausnahmen

| Flow                                                            | Klassifikation                                | Begründung und Feedback                                                                                                                                                          |
| --------------------------------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Login und Logout                                                | Navigation/Auth                               | Kein Speichern eines Formular-Datensatzes                                                                                                                                        |
| Rechtstext-Akzeptanz                                            | rechtlich relevante Entscheidung              | Eigener bestätigter Entscheidungsfluss; kein normaler Save-Erfolg                                                                                                                |
| Account-Datenschutzanträge und Berechtigungsänderungen          | Workflow-Antrag                               | Der sichtbare Antragsstatus ist maßgeblich; keine Save-Bestätigung                                                                                                               |
| Account-Datenexport                                             | kontextlose beziehungsweise asynchrone Aktion | Wird im Folge-Change `add-contextless-action-feedback` vereinheitlicht                                                                                                           |
| Passwort- und Einladungs-E-Mails                                | kontextloser Befehl                           | Wird im Folge-Change `add-contextless-action-feedback` vereinheitlicht                                                                                                           |
| IAM-Autorisierungsprüfung und Monitoring-Autorisierung          | Operation                                     | Ergebnis und Laufstatus besitzen eine eigene Ergebnisfläche                                                                                                                      |
| Instanz-Provisionierung, Reconcile, Synchronisierung und Import | langlaufende Operation                        | Fortschritt und Teilergebnisse gehören in `standardize-plugin-operation-feedback`                                                                                                |
| Medien-Upload und initiale Medienregistrierung                  | mehrstufige Upload-Operation                  | Initialisierung, Upload-Fortschritt und Registrierung bilden einen eigenen Operationszustand; die aktuelle Mediendetailseite ist read-only und besitzt keine normale Save-Action |
| Instanzanlage mit anschließender Einrichtung                    | mehrstufiger Setup-Flow                       | Der Save-Button folgt dem gemeinsamen Lifecycle; danach bleibt die konkrete Einrichtungs- und Provisionierungsanleitung im sichtbaren Create-Kontext                             |
| Löschen, Zurücksetzen und irreversible Änderungen               | destruktive Aktion                            | Bestätigung und Ergebnis gehören in `standardize-destructive-action-feedback`                                                                                                    |
| Filter, Suche und Tabellen-Navigation                           | Abfrage/Navigation                            | Keine persistierende Mutation                                                                                                                                                    |
| Gruppen- und Organisationsmitgliedschaften                      | untergeordnete Mutation                       | Pending und persistente Fehler sind verpflichtend; Erfolg ist durch die aktualisierte Elternliste sichtbar, daher kein zweisekündiger Saved-Zustand erforderlich                 |
| Waste-Create-/Edit-Dialoge ohne eigene Detailroute              | untergeordnete Mutation                       | Pending und persistente Fehler sind verpflichtend; nach Erfolg schließt der Dialog und die aktualisierte Elternliste ist der sichtbare Erfolgskontext                            |
| Ungespeicherte Änderungen und Versionskonflikte                 | erforderliche Entscheidung                    | Dialoge sind zulässig, weil eine echte Nutzerentscheidung notwendig ist                                                                                                          |

## Abschlusskriterium

Nach der Migration darf ein verbleibender Submit-Button ohne `StudioSaveButton` nur zu einer hier dokumentierten Ausnahme gehören. Separate Erfolgshinweise und Toasts für normale Save-Actions sind nicht zulässig. Technische Fehler bleiben bis zu einer neuen Nutzeraktion sichtbar und bieten eine sichere Wiederholungsmöglichkeit, sofern die Mutation idempotent oder anderweitig sicher wiederholbar ist.
